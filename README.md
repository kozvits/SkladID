# SkladID

Android-приложение для оператора склада: сфотографировать товар или бирку, распознать его (штрих-код / текст / фото через ИИ), определить адрес хранения, сформировать этикетку и напечатать её на принтере TSC.

## Возможности

- 📷 **Съёмка товара и бирки** (CameraX) — два кадра: сам товар и бирка/этикетка с текстом.
- 🔍 **Распознавание**: штрих-код и текст с бирки — на устройстве (ML Kit), определение товара по фото — через облачный ИИ (OpenRouter, любая vision-модель на выбор).
- ✍️ **Редактируемая карточка товара**: Название, Производитель, Категория, Характеристики, Применимость, Штрих-код, Количество + единица измерения (шт., компл., пар., дес., л., кг.).
- 🌐 **Языковые правила ИИ**: Название/Категория — на русском (плюс второй язык через «/», если он есть на бирке); Характеристики — на языке бирки, если она есть, иначе на русском.
- 📍 **Адрес хранения**: полный вариант — каскадный выбор Склад → Стеллаж → Полка → Ячейка по импортированной JSON-базе; быстрый вариант — прямой выбор Стеллажа (1–10) и Ячейки (1–70) прямо на экране распознавания, без базы.
- 💾 **Сохранение в список** без обязательного адреса хранения — кнопка «Сохранить» на экране распознавания сразу добавляет товар в список на «Последние товары».
- 📋 **Список товаров** с разворачиваемыми карточками: все поля, изменение количества/единицы на месте, печать этикетки прямо из списка.
- 🏷️ **Генерация этикетки** (Canvas): заголовок с автоуменьшением шрифта, штрих-код Code128 (ZXing), блок адреса хранения, производитель — под настраиваемый размер (мм) и DPI принтера.
- 🖨️ **Печать на TSC**: Bluetooth (Classic SPP) или сеть (TCP `IP:9100`), команды TSPL.
- 📤 **Отправка в Telegram**: весь список товаров — JSON-файлом и текстовой сводкой в заданный чат через Telegram-бота.
- ⚙️ **Настройки**: API-ключ OpenRouter, выбор/обновление vision-модели, импорт JSON-базы складов, Bot Token/Chat ID Telegram, параметры принтера и этикетки.

## Технологический стек

- **Kotlin**, **Jetpack Compose** (Material3)
- **Clean Architecture**: `data` / `domain` / `presentation`, паттерн MVVM
- **Hilt** — dependency injection
- **Room** — локальная БД товаров
- **OkHttp** (без Retrofit) — запросы к OpenRouter API и Telegram Bot API
- **ML Kit** — Barcode Scanning + Text Recognition (on-device)
- **CameraX** — съёмка
- **ZXing** — генерация штрих-кода Code128
- **kotlinx.serialization** — JSON
- **GitHub Actions** — сборка `assembleDebug` на каждый push
- `minSdk 26`, `targetSdk 35`

### Поток экрана «Добавить товар»

`Home → Capture (фото товара, фото бирки) → Recognition (ML Kit + ИИ, + Стеллаж/Ячейка/Применимость) → [Сохранить сразу] или [Далее → Storage (полный адрес) → LabelPreview (печать)]`

Промежуточные данные о товаре живут в `ProductDraftViewModel`, привязанной к `NavHost` — экраны не передают их через аргументы маршрута.

### Распознавание

1. ML Kit (Barcode + Text Recognition) выполняется **on-device** на фото бирки — даёт штрих-код и/или сырой текст (используются только как *подсказки*).
2. Фото товара всегда отправляется в OpenRouter (`POST /api/v1/chat/completions`, vision-модель) вместе с этими подсказками — модель обязана вернуть строгий JSON `{name, manufacturer, category, specs, applicability}`, из которого и заполняются поля товара, с учётом языковых правил (см. «Возможности»).
3. Штрих-код, количество/единица измерения, Стеллаж/Ячейка можно поправить вручную на экране распознавания. Если Стеллаж/Ячейка оставлены как «-», в карточку товара и экспорт они не попадают.

## Сборка

```bash
git clone <repo-url>
cd SkladID
./gradlew assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

CI (`.github/workflows/Build.yml`) на каждый push гоняет юнит-тесты и собирает debug-APK, публикуя его как артефакт сборки.

## Настройка

Всё — в приложении, на экране **Настройки**:

- **API-ключ OpenRouter** (`sk-or-...`) — хранится в `EncryptedSharedPreferences` (AES-256-GCM), не логируется (заголовок `Authorization` явно редактируется в HTTP-логах).
- **Модель распознавания** — список подтягивается кнопкой «Обновить модели» (`GET /api/v1/models`, только vision-модели).
- **База размещения** — импортируется как `.json`-файл через системный проводник. Формат:

```json
{
  "warehouses": [
    {
      "name": "Склад 1",
      "racks": [
        {
          "name": "Стеллаж A",
          "shelves": [
            {
              "name": "Полка 1",
              "cells": ["Ячейка 1", "Ячейка 2", "Ячейка 3"]
            }
          ]
        }
      ]
    }
  ]
}
```

- **Telegram-бот** — `Bot Token` (скрытый ввод, хранится в `EncryptedSharedPreferences`) и `Chat ID` (обычное поле, поддерживает отрицательные значения для групп/каналов).
- **Принтер** — Bluetooth (Classic SPP, из списка сопряжённых устройств) или сеть (`IP:порт`, по умолчанию `9100`).
- **Размер этикетки** — ширина/высота в мм + DPI принтера (по умолчанию 40×30 мм, 203 DPI).

## Тесты

```bash
./gradlew testDebugUnitTest
```

Покрыты юнит-тестами:
- `WarehouseJsonParserTest` — валидный/невалидный JSON, проверка обязательных полей, round-trip сериализации.
- `TsplCommandBuilderTest` — корректность команд `SIZE`/`GAP`/`CLS`/`BITMAP`/`PRINT`, упаковка изображения в 1bpp построчно с выравниванием по байту.

## Известные ограничения

- Правило автоподбора ячейки (`SuggestStorageCellUseCase`) — «первая свободная», без учёта категории товара (задел под расширение оставлен в сигнатуре).
- Bluetooth-печать не проверяет, что выбранное сопряжённое устройство — именно TSC-принтер (протокол SPP одинаков для многих устройств).
- Быстрые Стеллаж/Ячейка (1–10 / 1–70) на экране распознавания и полный адрес из JSON-базы (экран «Хранение») независимы: если после быстрого выбора пройти через «Далее → Хранение», выбор там перезапишет Стеллаж/Ячейку.
